# 04 · 生产化落地清单

> 演练验证了机制之后，从"能跑"到"能上线"需要补的功课。按模块给出 checklist 与量化建议。

## 1. 检索质量（决定产品体验）

- [ ] **建立评测集**：50~200 条真实问题，每条标注期望命中的文档/分段（golden set）；
- [ ] **量化指标**：Recall@k（黄金分段是否命中）、MRR、top1 命中率；建议每轮调参都跑同一评测集对比；
- [ ] **切分调优**：按文档类型差异化配置（API 文档 200~300 token、长规范按章节切）；开启父子切分（`hierarchical_model`）处理"大段落+细粒度检索"矛盾；
- [ ] **检索策略调优**：默认 hybrid（semantic_first）+ 配置 Rerank 模型；`score_threshold` 用评测集标定（一般 0.3~0.6 起步）；
- [ ] **元数据过滤**：利用 `metadata_filtering_conditions`（如按部门/文档类型/版本过滤），减少无关召回；
- [ ] **Query 改写**：复杂问句接入 LLM 改写（Dify 工作流节点）后再检索，可显著提升召回；
- [ ] **多路召回 + 兜底**：无命中时返回"未找到，建议人工"而非编造。

## 2. 性能与容量

- [ ] **写入侧**：批量上传（Dify batch 默认 100）；错峰索引；监控 worker 队列积压；
- [ ] **检索侧**：网关层加 Redis/本地缓存（同 query 短 TTL）；`top_k` 不要过大（10~20 足够）；
- [ ] **Weaviate 容量估算**：向量占用 ≈ 维度 × 4 字节 × 分段数（如 1536 维 × 4B ≈ 6KB/分段，10 万段 ≈ 0.6GB，加上索引/元数据约 1.5~2×）；
- [ ] **资源基线**（Weaviate 官方建议）：1 万向量级 2C/2G 起；10 万级 4C/8G；注意 HNSW 索引的 `efConstruction`/`maxConnections` 与内存关系；
- [ ] **压测**：检索 P99 < 200ms（同网络）、吞吐 ≥ 100 QPS 起步目标；关注 `QUERY_DEFAULTS_LIMIT=25` 等默认值。

## 3. 高可用与备份

- [ ] **持久化**：确认 Weaviate `PERSISTENCE_DATA_PATH` 挂载了宿主机卷（你的部署默认 `/var/lib/weaviate`，Dify compose 已配置 volume）；
- [ ] **备份**：定期备份 = Postgres dump + Weaviate 数据目录（或 Weaviate 快照 API）；先备份再升级 Dify/Weaviate 版本；
- [ ] **多副本**（生产）：Weaviate 可开多节点（raft 共识，至少 3 节点），Dify api/worker 水平扩容；
- [ ] **优雅降级**：向量库不可用时检索接口返回 503 与降级文案，不拖垮网关。

## 4. 安全与合规

- [ ] **密钥管理**：数据集 API Key / App Key 放密钥管理（Vault/环境变量），**严禁进代码库**；定期轮换；最小权限（按数据集隔离 Key）；
- [ ] **网络隔离**：Weaviate 不暴露公网（你的部署已在内网）；演练代理容器只绑 `127.0.0.1`，用完即删；
- [ ] **数据权限**：`permission: only_me / all_team_members / partial_members` 按团队设好；网关层按调用方鉴权；
- [ ] **输入输出安全**：知识库内容审核（敏感词/涉密文件不入库）；LLM 输出加提示词护栏，防止"提示注入"利用检索内容；
- [ ] **审计**：记录检索/问答日志（谁、何时、查了什么、命中什么）满足内审要求。

## 5. 成本

- [ ] **Embedding 费用**：入库一次性 token 成本 = 全文 token 总和；检索端 embedding 按查询次数计费——高频固定问题建议网关侧缓存；
- [ ] **Rerank 费用**：每次检索额外一次模型调用，仅在需要时开启；
- [ ] **存储费用**：定期清理已删除文档对应的向量（Dify 删除文档会同步删向量）；知识库版本化归档；
- [ ] **模型选择**：Embedding 用性价比模型（如 `text-embedding-3-small` 或本地 bge-m3），生成模型按场景分级（复杂回答用强模型，简单检索用轻模型）。

## 6. 可观测性

- [ ] **Dify 侧**：Dify 支持 OpenTelemetry（OTEL），导出 api/worker 链路；监控文档索引任务成功率/耗时；
- [ ] **Weaviate 侧**：开启 metrics（`/v1/metrics`）到 Prometheus；关注 object 数、delete/insert 速率、query 时延、磁盘水位；
- [ ] **网关侧**：日志结构化 + 关键指标（检索 QPS、P99、召回 top1 命中率、Rerank 触发率）；
- [ ] **检索质量看板**：评测集得分随版本趋势、线上"未命中"问题聚类（定期分析 badcase 反哺切分/改写策略）。

## 7. 治理与生命周期

- [ ] **文档生命周期**：过期文档定时下线（Dify 支持禁用/删除文档）；版本更新走"替换文档"（`original_document_id` 语义）；
- [ ] **知识库分级**：核心知识库（高可用+专人维护）与普通知识库区分策略；
- [ ] **发布流程**：切分/检索参数变更走评测集回归后才上线（避免"拍脑袋调参"）；
- [ ] **告警**：索引失败率 > 1%、检索 P99 超阈值、向量库磁盘 > 80% 自动告警。

## 8. 上线 Go-Live 检查表（一天内可完成）

1. [ ] 评测集 ≥ 50 条 + 基线指标已记录
2. [ ] 检索方式 = hybrid + Rerank + 阈值已标定
3. [ ] 密钥全部走环境变量/密钥管理，无硬编码
4. [ ] 网关接口有鉴权、限流、审计日志
5. [ ] Weaviate/Postgres 备份脚本已跑通一次并验证可恢复
6. [ ] 容量估算与资源基线已确认（含 3 个月增长）
7. [ ] 降级预案（向量库宕机 → 503 + 提示文案）演练过
8. [ ] 监控大盘与告警规则已配置并有人值班
