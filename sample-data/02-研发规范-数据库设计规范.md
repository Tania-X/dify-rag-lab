# 研发规范 · 数据库设计规范（示例文档）

> 演示语料：虚构公司"星云科技"研发中台知识库。内容贴近真实工程实践，用于 Dify 向量化演练。

## 1. 表设计原则

- 命名：表名复数小写（`orders`、`order_items`），业务前缀（`pay_`、`log_`）；禁止保留字。
- 字段：`id` 一律 BIGINT UNSIGNED 自增或雪花 ID；时间统一 `created_at` / `updated_at`（DATETIME(3)）。
- 金额：一律 DECIMAL(18,2) 或分为单位的 BIGINT，禁止 DOUBLE/FLOAT 存钱。
- 软删除：需要审计的表加 `deleted_at`，查询必须带 `deleted_at IS NULL`；无审计需求用物理删除。
- 每张表必须有三件套注释：表注释、字段注释、变更记录（`-- v2.3 增加 xxx`）。

## 2. 索引规范

- 索引命名：`idx_{表}_{列}`（单列）/ `idx_{表}_{列1}_{列2}`（联合）。
- 联合索引：区分度高的列放前面；范围查询的列放最后；禁止对 `text/blob` 建普通索引。
- 冗余索引治理：每周用 `pt-duplicate-key-checker` 扫一次，合并重叠索引。
- 隐式转换：`where` 条件类型必须与列类型一致（`varchar` 列不能用数字比较），否则索引失效。
- 覆盖索引优先：高频查询尽量"索引覆盖"，避免回表。

## 3. SQL 与事务

- 慢 SQL 阈值：单条 > 500ms 必须优化；每天慢日志（>200ms）复盘。
- 禁止：`SELECT *`、循环内查询（N+1）、`%xxx%` 双模糊、大事务（>1000 行 DML 或 >1s）。
- 事务：只读事务必须声明 `readOnly=true`；长事务必须拆分为多个短事务 + 幂等补偿。
- 分页：深分页用游标/`WHERE id > ?` 方案，禁止 `OFFSET 100000`。
- 批量写：一次 DML 不超过 1000 行；大批量导入走 `LOAD DATA` 或分批提交。

## 4. 分库分表

- 阈值：单表数据 > 2000 万行或容量 > 20GB 时评估拆分。
- 拆分键：按业务访问模式选择（订单按 `user_id` 分片、流水按 `tenant_id` 分片）。
- 分片算法：一致性哈希或取模；禁止用时间戳直接取模（热点）。
- 跨片查询：禁止跨片 JOIN；用汇总表 / ES / 应用层聚合。
- 全局唯一 ID：用雪花算法（workerId 由配置中心分配）或号段模式。

## 5. 数据迁移

- 变更流程：DDL 走工单审批 → 先在预发执行 → 灰度表（10% 流量）→ 全量。
- 在线 DDL：MySQL 8 用 `INSTANT`/`INPLACE`，大表禁止 `COPY` 算法（锁表）。
- 数据订正：必须备份受影响行（`SELECT ... INTO OUTFILE` 或快照表），保留 30 天。
- 回滚预案：任何迁移必须有回滚 SQL 与回滚演练记录，否则禁止上线。

## 6. 数据质量

- 唯一性：业务唯一键必须建唯一索引（如 `uk_order_no`），并在应用层双保险。
- 数据校验：入库前必须过校验（长度、枚举、金额非负）；脏数据率 > 0.1% 触发告警。
- 归档：超过 13 个月的订单流水按年归档到冷存储（OSS + 列存），热表保持瘦身。
