# 研发 FAQ（示例文档）

> 本文档用于 Dify RAG Lab 演练，内容为虚构但贴近真实场景。

## Q1：支付网关调用超时应该怎么办？

A：按以下顺序排查：

1. 确认是否已按规范设置超时（连接 3s / 读 10s）；
2. 检查重试是否携带了同一个 `Idempotency-Key`（重试必须复用，否则可能重复下单）；
3. 连续失败 3 次以上，检查网关侧状态页与告警群（`GATEWAY_UNAVAILABLE` 说明网关侧故障，不要盲目加重试压力）；
4. 确认服务到 `pay.internal` 的网络链路（DNS、防火墙、TLS 证书有效期）。

## Q2：报错 INVALID_SIGNATURE 怎么排查？

A：签名校验失败 90% 是这三个原因：

- 时间戳与服务端相差超过 5 分钟（检查服务器时钟/NTP）；
- 签名串拼接顺序与文档不一致（先按 key 排序，再拼接 `key=value&`）；
- 使用了错误的密钥（沙箱/生产密钥混淆，或轮换后未同步）。

## Q3：JWT 过期了怎么刷新？

A：Access Token（15 分钟）过期后，调用 `POST /auth/refresh` 携带 Refresh Token（7 天）换取新的 Token 对。注意：

- Refresh Token 只能使用一次；
- 若 Refresh 也失败（黑名单命中），说明 Token 已被注销，需要重新登录；
- 前端应在 401 时静默刷新一次，失败再跳登录页。

## Q4：回调通知丢了怎么办？

A：平台侧会按 1/2/4 分钟退避重推最多 5 次。如果 5 次后仍未收到：

- 检查回调地址 HTTPS 证书是否有效、是否被 WAF 拦截；
- 检查是否返回了 `{"code":0}`（返回非 0 视为投递失败）；
- 兜底方案：对账任务每日 2 次拉取支付平台订单状态，与本地订单表对账，标记不一致订单人工处理。

## Q5：怎么判断这次发布要不要回滚？

A：满足以下任一条件立即回滚：

- 错误率 > 5% 持续 5 分钟；
- P99 时延超过 1 秒持续 10 分钟；
- 支付成功率跌破 99.5%；
- 出现资金类异常（重复扣款、金额不一致）。

## Q6：日志里能看到用户手机号吗？

A：不能。日志规范要求手机号脱敏（`138****5678`），且敏感字段一律走脱敏过滤器；如有排查需要，通过 trace_id 在专用查询平台按权限查看明文。

## Q7：新建服务需要接哪些监控？

A：最低要求：QPS、错误率、P99 时延、队列积压、GC 停顿五类指标；错误率 > 1% 持续 5 分钟触发 P2 告警，> 5% 触发 P1。支付相关服务额外要求支付成功率与网关可用性大盘。
