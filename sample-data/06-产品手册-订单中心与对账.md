# 产品手册 · 订单中心与对账（示例文档）

> 演示语料：虚构公司"星云科技"研发中台知识库。内容贴近真实工程实践，用于 Dify 向量化演练。

## 1. 订单状态机

订单状态及流转（禁止跳转，非法流转返回 `A3001`）：

```
CREATED(已创建) → PAID(已支付) → SHIPPED(已发货) → COMPLETED(已完成)
      ↘ CANCELLED(已取消)          ↘ REFUNDING(退款中) → REFUNDED(已退款)
```

- 状态变更必须走状态机服务（星云 order-flow），禁止业务代码直接改状态字段。
- 每次流转记录 `order_status_logs`：`from, to, operator, reason, trace_id`，保留 7 年。
- 终态（COMPLETED / CANCELLED / REFUNDED）之后禁止任何流转。

## 2. 超时关单

- 支付超时：订单创建后 30 分钟未支付自动关单（定时任务每分钟扫一次）。
- 关单前检查：必须确认该订单无"支付中"的流水（防止关单与回调竞态）。
- 关单补偿：关单后 5 分钟内若收到支付回调，走"复活流程"（重新入账 + 通知用户）。
- 关单指标：超时关单率（目标 < 40%）、关单后支付率（目标 < 0.1%）。

## 3. 退款

- 退款触发：用户申请 / 超卖自动退 / 风控强制退。
- 退款金额：≤ 实付金额；含优惠分摊规则：按商品金额比例分摊券/积分。
- 退款幂等：`refund_no`（唯一）保证重复请求不重复退款；退款原路返回（微信/支付宝/余额）。
- 退款时效：原路退回 T+0，余额即时到账；超 72 小时未到账自动告警并人工介入。
- 部分退款：允许，但累计退款额不得超过实付额（含运费分摊）。

## 4. 对账

- 对账频率：支付平台账单 vs 本地支付流水，每日 3 次（06:00 / 14:00 / 22:00）。
- 对账逻辑：双边比对（单号 + 金额 + 状态）；差异分三类：单边有、双边金额不符、状态不一致。
- 差异处理：单边有 → 自动查单（调支付平台查询接口），查单 3 次仍无 → 人工工单。
- 资金平衡：`本地成功流水总额 == 平台成功流水总额`，不平衡必须当日闭环。
- 对账报表：每月 1 日输出上月对账报告（差异笔数、金额、根因分布）给财务。

## 5. 关键接口与 SLO

- `POST /v1/orders`（下单）、`POST /v1/orders/{id}/pay`（支付）、`POST /v1/orders/{id}/refund`（退款）。
- SLO：下单 P99 < 200ms；支付回调处理 P99 < 1s；订单查询 P99 < 150ms。
- 依赖：订单服务依赖库存、支付、优惠三个下游；任一依赖熔断时下单降级为"先锁单后核销"。
- 监控：下单成功率 ≥ 99.95%、支付回调成功率 ≥ 99.9%、对账差异率 < 0.01%。

## 6. 测试与灰度

- 新订单流程必须覆盖：状态机全流转、超时关单竞态、退款幂等、对账差异四类用例。
- 灰度：订单流程变更按 5% → 30% → 100% 灰度，灰度期间对账差异率监控升级为 P1。
