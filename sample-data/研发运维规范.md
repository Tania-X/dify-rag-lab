# 研发运维规范（示例文档）

> 本文档用于 Dify RAG Lab 演练，内容为虚构但贴近真实场景，便于验证检索效果。

## 1. 支付网关接入规范

### 1.1 接入前置条件

- 申请商户号：联系财务在支付平台开通，T+1 生效。
- 获取密钥对：RSA 2048 位，私钥保存在密钥管理系统，禁止放入代码仓库。
- 环境区分：沙箱环境 base URL 为 `https://sandbox.pay.internal/v1`，生产环境为 `https://pay.internal/v1`。

### 1.2 调用超时与重试

- **超时设置**：HTTP 连接超时 3 秒，读超时 10 秒；超过视为失败。
- **重试策略**：最多重试 3 次，退避间隔 1 秒 / 2 秒 / 4 秒（指数退避 + 抖动 ±20%）。
- **幂等**：所有写操作请求头必须携带 `Idempotency-Key`（UUID），重试时复用同一个 Key。
- 3 次重试仍失败：立即返回 `GATEWAY_UNAVAILABLE`，并投递到 MQ 延迟队列（5 分钟后补偿）。

### 1.3 常见错误码

| 错误码 | 含义 | 处理建议 |
|---|---|---|
| `INVALID_SIGNATURE` | 签名校验失败 | 检查签名串拼接顺序与时间戳窗口（±5 分钟） |
| `INSUFFICIENT_BALANCE` | 商户余额不足 | 通知财务充值 |
| `ORDER_ALREADY_EXISTS` | 订单号重复 | 复用原订单状态，不要重新下单 |
| `RISK_CONTROL_REJECTED` | 风控拦截 | 人工审核，勿自动重试 |

### 1.4 回调通知

- 支付结果通过异步回调推送，回调地址在商户后台配置，必须是 HTTPS。
- 回调报文用平台公钥验签，验签失败丢弃并记日志。
- 收到回调后需返回 `{"code":0}`，否则平台按 1/2/4 分钟退避重推，最多 5 次。

## 2. JWT 鉴权规范

- 签发：登录成功后签发 Access Token（有效期 15 分钟）与 Refresh Token（有效期 7 天）。
- 刷新：Access Token 过期后，用 Refresh Token 调 `POST /auth/refresh`，返回新 Token 对。
- 失效：用户改密 / 登出 / 被踢下线时，将 Refresh Token 加入黑名单（Redis，TTL 对齐有效期）。
- 禁止在 JWT payload 中存放敏感信息（明文手机号、密码散列等）。

## 3. 发布与回滚流程

- 灰度发布：新版本先发 10% 流量，观察 30 分钟（错误率 < 0.5%、P99 < 300ms）再全量。
- 回滚：发布失败立即回滚到上一版本；回滚后 10 分钟内禁止再次发布。
- 变更记录：每次发布必须关联工单号，发布窗口为工作日晚 22:00 后。

## 4. 日志规范

- 格式：结构化 JSON，必含 `trace_id`、`service`、`env`、`level`、`timestamp`。
- 敏感字段脱敏：手机号中间 4 位打码（`138****5678`），银行卡号保留后 4 位。
- 禁止打印完整请求体（可能含密钥）；调试日志用 `log.debug`，线上默认 `info`。

## 5. 数据库规范

- 连接池：上限 20，等待超时 5 秒；禁止在循环里开连接。
- 慢 SQL：执行超过 500ms 的 SQL 必须优化或拆分。
- 索引：like 前缀模糊查询必须走全文索引或 es；`%xxx%` 双模糊禁止。

## 6. 监控与告警

- 必配指标：QPS、错误率、P99 时延、队列积压、GC 停顿。
- 告警阈值：错误率 > 1% 持续 5 分钟 → P2；错误率 > 5% → P1 立即拉群。
- 大盘：支付成功率（目标 ≥ 99.9%）、网关可用性（目标 ≥ 99.99%）。
